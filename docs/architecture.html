    2. 運用フロー（初期構築 〜 日常運用 〜 メンテナンス）

    サーバー常時稼働やDB保守が不要なため、一度配置すればほぼメンテナンスフリーで運用できます。

    Phase A：初回配置

    無料枠だけでセルフホスト構築

    • Google Drive に専用フォルダと管理スプレッドシートを作成。
    • GAS に copy_gas_to_clipboard.bat でコードを貼り付け、Drive API v3 を有効化。
    • スクリプトプロパティ（ALLOWED_EMAILS, FIREBASE_API_KEY, ALLOWED_ORIGINS）を登録し、setupDatabase() を1回実行。
    • 毎時トリガー（cleanupExpiredBoxes）を設定し、Firebase Hosting へデプロイ。
    Phase B：日常の受け渡し

    箱をつくって鍵（URL/QR）を渡す

    • 渡すとき（箱主→ゲスト）: 箱名・有効期限（30分〜30日）・任意6桁パスコードを設定してファイルをアップロード → URL/QR を共有。
    • もらうとき（箱主←ゲスト）: 空の箱を作成して URL/QR を共有 → ゲストが未ログインのまま動画（最大15 GB）を送信。
    • 管理: 受け取ったファイルはアプリから非公開のまま個別 DL、または Drive フォルダを直接開いて一括管理。
    Phase C：自動お掃除 & 更新

    放置しても自動で安全側へ閉じる

    • 期限切れ自動処理: 1時間おきトリガーで期限超過箱を EXPIRED 化し、一時公開権限を即時解除。Drive フォルダは保持されるため、必要なら箱主が同じ URL のまま「再開・延長」可能。
    • 一時共有の自動回収: ゲスト DL から6時間猶予経過後、Drive.Permissions.remove() で anyone 権限を確実に削除（失敗時は次回再試行）。
    • 箱の削除: 不要になった箱は念押し確認モーダルから削除可能。管理シートの記録を削除し、Google Drive 上の箱フォルダをゴミ箱へ移動します。

    3. 通信経路とセキュリティ境界の早見表

    「誰が・どのサービスへ・どんな制約で通信するか」を整理した一覧です。ファイル本体は GAS を経由せずブラウザと Google Drive が直接やり取りします。

    通信経路 プロトコル / 方式 認証・検証 主なセキュリティ対策
    ブラウザ → Firebase Hosting HTTPS GET（静的配信） 不要（公開静的ファイル） 厳格な CSP・X-Frame-Options: DENY・Referrer-Policy: no-referrer・外部 CDN 依存ゼロ
    箱主 → Firebase Auth Google OAuth ポップアップ Google アカウント ID トークンを発行（未確認アプリ警告なし）
    箱主 → GAS (doPost) HTTPS POST (text/plain) ID トークン ＋ ALLOWED_EMAILS accounts:lookup 検証・disabled 拒否・google.com 確認・トークン認証で CSRF 耐性
    ゲスト → GAS (doPost) HTTPS POST (text/plain) box_id (UUID v4) ＋ 任意6桁 HMAC-SHA256（ソルト＋ペッパー）・ロック内直列化・5回失敗で即 LOCKED・数式インジェクション対策
    ブラウザ → Google Drive（送信） HTTPS PUT（16 MB チャンク分割） GAS 発行の一時 Resumable URI ALLOWED_ORIGINS 完全一致検証・X-Upload-Content-Length 物理制限・完了時に実サイズ＆親フォルダ検証
    ブラウザ ← Google Drive（取得） HTTPS GET（ブラウザ標準 DL） 箱主：非公開/本人限定
    ゲスト：一時 anyone（SEND のみ）    		 RECEIVE 箱はゲスト DL 不可・一時公開は Write-Ahead 記録＋6時間後自動削除（無効化/ロック時は即削除）
